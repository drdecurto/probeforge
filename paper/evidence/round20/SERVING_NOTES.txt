GLM-5.3 serving provenance (campaign LOG.md, 29–30 October 2026)
The completed runs used eager execution (--enforce-eager), with TP4 x PP4 across 16 H100 GPUs. VLLM_HOST_IP was set per node. FlashInfer's FP8 block-scale GEMM attempted to fetch cubins from a network unavailable on the compute nodes; the successful configuration set VLLM_BLOCKSCALE_FP8_GEMM_FLASHINFER=0, using vLLM's non-FlashInfer FP8 block GEMM fallback. The failed startup/request attempts are not the reported completed evaluation.
This records a serving implementation and performance constraint, not an experimental manipulation or a demonstrated numerical-equivalence test between kernels. Main/core60/diag60 used low effort; the 26- and 52-item subsets used max effort and a 4096-token cap. See extra_low.json and extra_max.json and the archived completed responses.
The original campaign excerpt is preserved in campaign_excerpt.txt. The three additional all_*.jsonl files are copied from the same local round-20 archive and added to manifest.json; no remote transfer was needed.
